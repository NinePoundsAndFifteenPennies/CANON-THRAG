# CANON 第二版调整说明

这次保留三个模块，并把 H 调整回你的定义：**合并不同名字但同一个意思的 Topic/Subtopic，阻止相似但不同义的误合并。**新增主模式名为 `normalize`，不再默认先按父主题把共享子主题全部拆开。

下面说明上一版结果暴露的问题、第二版改动和运行方法。

## 1. 已有结果支持改哪些地方

以下来自之前的 MultiHop 服务器产物，不是第二版结果：

- 全模块 F1 约 69.45%，不做规范化约 69.40%，只拆分加软连接约 69.48%。这不足以支持继续把全量拆分、相似度硬合并当作默认有效策略。
- 原选择器适配改变了候选顺序，例如 Technology 从原来源顺序中的第 2 位移到了不规范化视图的第 4597 位。这个差异可以直接修复，无须靠调相似度阈值补偿。
- 不做规范化、使用原选择器并开启证据分配时，最高分证据句的来源 chunk 只有 323/1000 题被恢复。覆盖收益直接随分支数累加，会挤掉相关性更高的原文。
- 上一版增强路由的原句预览在全部 1000 题中被输入预算裁掉。先改卡片组织与裁剪策略，比直接扩大模型窗口更有依据。

MultiHop 的 **1000 题由 881 道可回答题和 119 道正常的无答案题组成**。本次不删除无答案题，不把正常拒答当作执行失败，也不改变最终回答提示词。后续应按原始 gold/type 标注分别统计可回答题的质量、误拒答，以及无答案题的正确拒答和错误作答；总拒答数不能代替这些指标。

## 2. 新 H：真正合并异名同义节点

### 2.1 保留共享结构

`hierarchy=normalize` 从原始抽取记录建立共享 Topic/Subtopic。同一个子主题可以保留多个父主题，不会仅因父主题不同就被拆成几十份。

处理顺序是：

1. 用现有标签向量召回同层近邻候选。
2. 检查明确的范围冲突，例如不同年份、相反极性和相反时间方向。
3. 为候选对提供标签、父主题、代表实体及来自不同上下文组的证据原句，离线审核是否真正同义。
4. 只对确认同义的节点做保守聚合；加入一个簇前，所有跨簇成员对都必须已有肯定判断。
5. 合并后保留 aliases、原节点映射、全部父节点和实体/句子来源。规范标签仍从已有名称中选择。

Subtopic 不再受“必须具有相同父 Topic 才能合并”的硬限制。比如 Film director 与 Movie director 即使由不同父主题引出、下属实体也不重合，只要审核确认整个概念等价，就可以合并。

### 2.2 相似度只负责找候选，不负责宣布同义

语义审核区分五种结果：

| 结果 | 处理 |
|---|---|
| `equivalent`：同义，范围和粒度一致 | 可以进入簇级合并检查 |
| `broader_narrower`：上下位关系 | 不硬合并 |
| `related`：相关但不同义 | 不硬合并 |
| `different_sense`：不同含义 | 不硬合并 |
| `uncertain`：证据不足或含义混杂 | 保留原节点 |

同一篇文章、相同实体、相似的句子原型都不是同义的充分证据。例如赔率、规则、策略，或者法律辩护、法律体系，不能仅因向量相近就合并。

新模式保留句子/实体原型作为候选排序与审核依据，但不再用旧的上下文相似度硬门槛把“实例不同”的真正同义项直接挡掉。旧 `MERGE_CONTEXT_THRESHOLD` 的相似度硬合并语义仍用于显式选择的旧 `split_merge` 模式。

### 2.3 离线审核有成本，也有明确边界

审核复用当前 `DEFAULT_MODEL`，温度固定为 0，批量返回受 JSON Schema 约束的候选 ID 和关系类型，不生成长解释。只在准备层级产物时调用，不在每个问题中重新审核。

审核结果按证据输入、模型、提示规则及候选上下文缓存。资源预算在 Topic/Subtopic 候选之间交错分配；超出预算的候选保留分离，并在产物中记录未审核数量。预算是资源上限，不是经过实验选择的准确率最优值。

审核响应失败或不确定时，不退回“只看 cosine 就合并”。已有成功判定可复用；`--force` 重建时会允许重试之前请求失败的判定，但不会无故重新请求所有有效判定。

开启软连接时，新模式只从已确认同义、但尚未通过完整簇合并的连接中选择弱边，并阻止已知不同义/上下位冲突。软边可能很少或为零；它仍只供扩散路由使用。**H 的硬合并本身不依赖 A 路由是否开启。**

首次准备新 H 需要可用的模型服务。已准备好并复用层级产物后，A 的在线路由仍不调用 LLM。不能把“在线零调用”理解为“新 H 离线也零调用”。

### 2.4 如何检查 H 实际做了什么

新产物的 `canonical_map.json` 中，`normalization` 保存候选数、已审核/未审核数、规则拦截示例、逐对语义判断及本次审核调用记录。`review_cache` 指向离线判定缓存，里面还保留断点前后的累计调用记录。`aliases`、`members` 和旧 ID 映射保留在层级产物中。

模型语义审核仍可能误判，不能把这些判断当成真实标签。第二版提供了可检查、可复用的判定记录；合并准确性仍需要服务器运行后的抽样核对。

## 3. 原选择器适配与证据卡片

### 原选择器

新层级产物记录原抽取中的出现顺序和每条父子关系的首次出现顺序。对 `hierarchy=none`，展示标签还保留原建图的最后一次标签写入行为。

向原选择器提供候选时使用来源顺序，而不是哈希或字母顺序。不同父主题下的同名子主题不再附加长哈希；单次父主题请求内确实重名时，只用短的局部变体编号区分。内部仍通过节点 ID 定位。

这修的是 CANON 内部的选择器适配，不修改作者原检索入口，也不新增修复版基线预设。

### B 和融合版的卡片

候选改为按父主题分组，父主题名称只写一次。每条保留路径继续携带短原句、匹配实体和证据分数。

输入超预算时裁减低排名路径，不再先把所有原句预览删掉。裁剪保留原有的交错路径排序，使靠前的候选能覆盖多个父主题。最终仍通过一次联合请求选择路径，重试预算不增加。

旧版的 8192 token 输入预算与候选规模不匹配。例如 MultiHop 的 `full_short` 第 0 题最初有 542 个主题—子主题组合，删除全部原句预览后，又裁到 159 个才装进预算。模型上下文上限当时是 49152，8192 是 CANON 自己设的路由输入限制。

第二版使用 10240。改动保证留下的候选保留原句预览，但装不下的候选仍会被裁掉；不能把它理解为全部候选信息都已保留。

PPR 的重启比例、迭代上限、停止条件、种子数量暂不调整；已有记录显示它正常收敛，没有数据支持先改这些数值。

## 4. 证据分配：保护相关性，再补覆盖

两个子功能仍独立开关。桥梁加权规则和权重暂时保留，先修已有明显问题的覆盖选择。

开启 `balance` 后：

1. 先按未加桥梁分的 query–句子相似度，保护一部分不同来源 chunk 的名额。
2. 这些受保护 chunk 的原始高分句也会被保留，且不突破 K1/K2。
3. 剩余名额再按相关性与新增分支覆盖收益选择。

覆盖分支的权重按实际证据匹配分分配，并归一化到总和为 1。新的边际分数是：

`(1 - coverage_weight) × chunk相关性 + coverage_weight × 归一化新增覆盖收益`

因此，选择五十条路径时，覆盖项不会仅因分支更多就变成选择十五条路径时的数倍。当前新增的保护比例对应“一半名额优先保相关性”：K2 为 10 时保护 5 个，K2 为 5 时向上取整保护 3 个。这是有结构依据的起始设置，仍需检验，不是已验证最优值。

诊断记录增加 `protected_chunks`、`coverage_normalized`、`coverage_path_weight_sum` 等字段。关闭 `balance` 时不启用保护配额；原有普通排序路径继续可用。

## 5. 参数为什么这样处理

可复制配置仍以 [thrag/.env.example](../thrag/.env.example) 为准。本次没有改动服务器部署配置、K1/K2 或回答参数。

| 配置/行为 | 本次处理及依据 |
|---|---|
| `CANON_HIERARCHY` | 推荐默认改为 `normalize`，对应异名同义合并；停止把全量父域拆分作为默认 H |
| `CANON_MERGE_LABEL_THRESHOLD`、近邻数 | 保留已有值作为候选召回条件，不假装已经从结果找到新的最优阈值 |
| `CANON_MERGE_CONTEXT_THRESHOLD` | 新模式不再将它作为硬合并的最终依据；旧模式仍使用原语义 |
| `CANON_SYNONYM_*` | 新增离线审核批大小、资源预算和上下文长度限制；这些是工程预算，不是跑分调参结果 |
| `CANON_COVERAGE_WEIGHT` | 保留数值，改为作用于归一化的覆盖收益；与旧公式中的同一数值含义不同 |
| `CANON_COVERAGE_ANCHOR_FRACTION` | 新增相关性保护比例，针对旧版本高分句来源 chunk 被大量挤掉的现象 |
| 卡片输入预算、原句长度 | 保留已有预算，优先改变组织与裁剪方式，不直接放大窗口 |
| PPR 与桥梁参数 | 暂时保留，现有结果不足以支持同时修改 |

`split`、`split_merge` 保留原来的层级算法作为显式备选；`none + soft_links=on` 仍是保留共享层级、只加原相似度软边的组合。它们与新 `normalize` 的语义审核不同。

旧模式名称被保留，不代表新版本能逐字重现旧实验：排序、卡片和证据选择已有变化。旧结果继续保留，严格复现旧版本应使用其对应 commit。

## 6. 在服务器怎么运行

**旧服务器 `.env` 若仍写着 `CANON_HIERARCHY=split_merge`，它会继续选择旧 H。**可按新模板更新 CANON 字段，或在命令中显式写 `--hierarchy normalize`。不需要替换 `.env` 中你已调整的部署参数。

在服务器的 `thrag/` 目录运行新完整组合：

```bash
python -u -m canon.pipeline --dataset multihop_1000 --hierarchy normalize --soft-links on --routing hybrid --bridge on --balance on --run-id normalize_v2_full --steps generate_short --short-prompt prompt/answer_short.py
```

如果先单独准备索引，使用同一层级配置运行 `--steps prepare`。只准备索引时不要附带 `--short-prompt`。原始抽取与 KV 不重建；现有完整来源与 E5 缓存可以复用，新层级产物使用单独的版本身份。

### 可选：比较证据分配时复用上次的主题/子主题选择

正常实验每次运行一条命令即可，不需要指定 `--routing-from`。如果只想比较 `bridge`、`balance` 的作用，可以让同一道题沿用上次选出的主题—子主题组合，再重新选择证据并生成答案，减少重新选择主题带来的干扰。例如：

```bash
python -u -m canon.pipeline --dataset multihop_1000 --hierarchy normalize --soft-links on --routing hybrid --bridge off --balance off --routing-from /data/panzheng/canon-thrag/results/canon/runs/multihop_1000/normalize_v2_full --run-id normalize_v2_no_e --steps generate_short --short-prompt prompt/answer_short.py
```

这只是可选用法。每道题复用的是它自己的选择结果，不是所有题共用同一组主题。来源须是当前新版生成的结果；问题、层级图及路由设置要一致，所以更换 H 或 R 时仍需重新选择。复用不读取来源答案，也不重新调用路由模型，耗时不能直接当作完整重跑的耗时。

## 7. 验证状态

本次补充了来源顺序、同义审核、相似但非同义、无实体交集的同义节点、簇级冲突、审核缓存、受约束覆盖、路由复用和保留无答案题的回归用例。

**本次未运行项目代码、pytest、模型调用或服务器实验。**这里描述的是新代码行为和设计依据，不能据此宣称已经涨点或验证通过。也没有改动原答案评测口径或自动安排作者源码对照。
